# 前端开发技术文档（art-design-pro）

> 本文档基于 `web/` 目录实际代码梳理而成，作为前端二次开发时的统一约定。项目基于 Vue 3 + Vite + Element Plus，采用**组件化架构**：业务页面拆分为可复用的独立组件，CRUD 页面优先使用通用 `ArtCrud` 组件。

## 1. 项目概览

| 项目 | 说明 |
| --- | --- |
| 包名 | `art-design-pro` |
| 核心框架 | Vue `3.5`、TypeScript `6.0` |
| 构建 | Vite `7.1` |
| UI 组件 | Element Plus `2.11`（按需自动导入） |
| 状态管理 | Pinia `3.0`（`pinia-plugin-persistedstate` 持久化） |
| 路由 | vue-router `4.5` |
| HTTP | axios `1.12`（统一封装 `utils/http`） |
| 样式 | Tailwind CSS `4` + Sass |
| 图表 | ECharts `6` |
| 国际化 | vue-i18n `9` |
| 包管理器 | **pnpm**（`>=10`），Node `>=20.19` |

```bash
pnpm dev        # 启动开发服务（vite --open，端口见 .env）
pnpm build      # 类型检查 + 生产构建（vue-tsc --noEmit && vite build）

```

## 2. 目录结构规范

```
web/src/
├── api/               # 全局接口调用（如 auth.ts / system-manage.ts / chat.ts）
├── assets/            # 静态资源（styles / images / icons）
├── components/        # 通用组件
│   ├── business/      #   业务通用组件（art-crud / art-icon-picker / art-iframe）
│   └── core/          #   基础组件（forms / layouts / tables / cards / charts / media ...）
├── config/            # 应用配置
├── directives/        # 自定义指令
├── enums/             # 枚举定义
├── hooks/             # 组合式函数
├── locales/           # 国际化语言包
├── mock/              # Mock 数据
├── plugins/           # 插件
├── router/            # 路由（index / core / guards / modules / routes / routesAlias）
│   └── modules/       #   业务路由模块（system / monitor / tool）
├── store/             # Pinia（index + modules）
│   └── modules/       #   user / menu / dict / chat / setting / table / worktab
├── types/             # 类型定义（index + api + router + store ...）
├── utils/             # 工具（http / form / storage / table / ui / sys / navigation ...）
└── views/             # 页面视图（auth / dashboard / system / monitor / tool / layout ...）
```

**核心开发路径约定：**

- 业务页面放 `views/<模块>/<功能>/`，一个功能 = `index.vue`（主页面）+ `api.ts`（接口）+ `components/`（子组件）。
- 通用/可复用能力放 `components/core/` 或 `components/business/`，供多处调用。
- 接口类型放 `types/api/`，与后端响应结构对应。

## 3. 请求层规范（`utils/http`）

统一使用 `@utils/http` 的 `request` 方法发起请求，已封装：

- **请求拦截器**：自动注入 `Authorization: Bearer {accessToken}`；对象自动 `JSON.stringify` 并设置 `Content-Type: application/json`。
- **响应拦截器**：统一解包 `{code, msg, data}`；`code=200` 视为成功并返回完整 `response`；`code=400` 抛出错误并提示；`code=401` 自动登出（带 3s 防抖）；支持 blob/arraybuffer 透传。
- **通用方法**：支持 GET / POST / PUT / DELETE，配置项 `showErrorMessage` / `showSuccessMessage`。

### 接口调用文件写法（`api.ts` 模式）

```ts
import { SysUser, UserQueryParams } from '@/types/api'
import { TableDataInfo } from '@/types/api/system/common'
import response from '@utils/http'

// 查询列表
export function listUser(query: UserQueryParams) {
  return response<TableDataInfo<SysUser>>({
    url: '/system/user/list',
    method: 'get',
    params: query
  })
}

// 新增 / 修改 / 删除
export function addUser(data: SysUser) {
  return response({ url: '/system/user', method: 'post', data })
}
export function updateUser(data: SysUser) {
  return response({ url: '/system/user', method: 'put', data })
}
export function delUser(userId: number | number[]) {
  return response({ url: '/system/user/' + userId, method: 'delete' })
}
```

**约定：**
- URL 与后端路由一致（如 `/system/user/list`），分页查询用 `params` 传 `query`。
- 泛型标注返回类型：列表 `TableDataInfo<T>`，详情 `AjaxResult<T>`，分页含 `total` + `rows`。

## 4. 类型定义规范（`types/api/`）

- 与后端响应结构一一对应，集中放在 `types/api/`。
- **checkbox/开关字段类型约定**：是/否类字段（如角色的 `menuCheckStrictly`、`deptCheckStrictly`）类型声明为 `boolean`，与后端 `bool` 字段、MySQL `BOOLEAN` 列直接对应；表单 `v-model` 直接使用布尔，提交时**无需转 `0/1`**。后端为 `bool` 时不要传数字（gin 绑定时 `1` 无法解析为 `bool`）。
- 通用响应类型（`types/api/system/common.ts`）：

```ts
export interface AjaxResult<T = any> {
  code: number
  msg: string
  data?: T
}

export interface TableDataInfo<T = any> {
  code: number
  msg: string
  total: number
  rows: T[]
}

export interface TreeSelect {
  id?: number
  label?: string
  disabled: boolean
  children: TreeSelect[]
}
```

- 每个业务模块在 `types/api/` 下维护自身的类型文件（如 `types/api/system/user.ts`）。
- 字段命名与后端 JSON 保持一致（驼峰）。

## 5. 组件化架构（核心约定）

### 5.1 通用 CRUD 组件 `ArtCrud`

CRUD 页面**优先使用** `components/business/art-crud/index.vue`，它基于 `art-search-bar` / `art-table` / `art-table-header` / `art-form` 封装，开箱即用：

```vue
<template>
  <ArtCrud :config="crudConfig" />
</template>

<script setup lang="ts">
import ArtCrud from '@/components/business/art-crud/index.vue'
import { ref } from 'vue'

const crudConfig = ref({
  // API 配置（list 必填）
  api: {
    list: fetchUserList,     // 列表查询
    add: addUser,            // 新增
    update: updateUser,      // 修改
    delete: deleteUser       // 删除
  },
  // 表格列
  columns: [
    { type: 'selection' as const },
    { type: 'index' as const, label: '序号', width: 60 },
    { prop: 'name', label: '姓名', minWidth: 120 }
  ],
  // 搜索表单
  search: {
    items: [
      { key: 'name', label: '姓名', type: 'input', placeholder: '请输入姓名' },
      { key: 'status', label: '状态', type: 'select', options: statusOptions }
    ]
  }
})
</script>
```

**组件拆分原则：**
- 一个页面按「搜索区 / 表格区 / 表单区 / 独立弹窗」拆分可复用组件。
- 通用能力（如表格、表单、上传、图标选择）优先复用 `components/core/` 与 `components/business/`，避免重复造轮子。
- 独立业务子模块（如用户管理中的"分配角色"）抽到 `views/<功能>/components/`。

### 5.2 页面组成约定

每个业务功能目录：

```
views/system/user/
├── index.vue          # 主页面（组合下方组件）
├── api.ts             # 本功能接口
└── components/        # 本功能子组件（view.vue 详情、authRole.vue 分配角色等）
```

## 6. 视图开发规范（`views/`）

- 页面放在对应模块下（`system` / `monitor` / `tool` / `dashboard` 等）。
- 使用 `<script setup lang="ts">` 组合式 API。
- 依赖 Element Plus、`@vueuse/core`、`vue-router`、`pinia` 时**无需手动 import**（`unplugin-auto-import` 自动注入）。
- 业务状态尽量放 `store/modules/`（如 `useUserStore`、`useMenuStore`），页面只做展示与交互。
- 表格交互可复用 `@utils/table` 与 `useTable` composable（见 `hooks/`）。

---

## 7. 状态管理（Pinia）

- 所有 store 放 `store/modules/`，在 `store/index.ts` 汇总导出。
- 常用 store：`user`（用户信息/Token）、`menu`（菜单/路由）、`dict`（字典）、`setting`（应用设置）、`table`、`worktab`、`chat`。
- 需要持久化的状态使用 `pinia-plugin-persistedstate`（如用户 Token）。
- 通过 `useXxxStore()` 访问，避免跨页面直接传参。

---

## 8. 路由与权限

- 路由分静态路由与动态路由：`router/` 下 `modules/system.ts` / `monitor.ts` / `tool.ts` 定义各模块路由，`router/core`、`guards` 处理路由守卫与权限。
- 路由记录类型：`RuoYiAppRouteRecord`（见 `types/router`），字段含 `path` / `name` / `component` / `permissions` / `meta`。
- 权限模式：`VITE_ACCESS_MODE = backend`（后端权限模式），菜单与权限由后端下发，前端根据权限动态生成路由与按钮显隐。
- 新增业务页面：
  1. 在 `views/` 下创建页面；
  2. 在 `router/modules/` 对应模块注册路由；
  3. 后端 `sys_menu` 菜单配置中挂对应权限标识（如 `system:customer:list`），前端按钮用权限指令/判断控制。

## 9. 环境配置（`.env`）

| 变量 | 说明 |
| --- | --- |
| `VITE_VERSION` | 版本号 |
| `VITE_PORT` | dev 端口（默认 80） |
| `VITE_BASE_URL` | 部署基础路径 |
| `VITE_ACCESS_MODE` | 权限模式（`frontend` / `backend`） |
| `VITE_WITH_CREDENTIALS` | 跨域是否携带 Cookie |
| `VITE_API_URL` | API 请求基础路径（dev 为 `/dev-api`） |
| `VITE_API_PROXY_URL` | Vite 代理目标（dev 为 `http://localhost:8080`） |

- 开发环境通过 Vite 代理解决跨域：`/dev-api` → 后端 `8080`。
- **生产环境已移除 apifox mock**：`web/.env.production` 的 `VITE_API_URL` 已改为同源 `/`（不再指向 `https://m1.apifoxmock.com/m1/...`）。生产由后端直接托管前端静态文件并在同一端口（`8080`）提供接口，因此 HTTP 与 WebSocket 均走同源，无需额外代理或跨域配置；后端升级端口后无需改前端 env。
- `VITE_API_URL` 同时被 `utils/http`（axios `baseURL`）与 `utils/websocket`（WS 地址）使用：生产为 `/` 时两者均同源。

## 11. 新增一个业务页面的完整流程（Checklist）

假设新增「客户管理」列表页：

1. **类型**：在 `types/api/` 新增客户类型（`Customer`、`CustomerQueryParams`）。
2. **接口**：在 `views/<模块>/customer/` 下新建 `api.ts`，用 `response` 封装 `listCustomer` / `getCustomer` / `addCustomer` / `updateCustomer` / `delCustomer`。
3. **页面**：新建 `index.vue`，优先使用 `ArtCrud` 组件，配置 api、columns、search。
4. **子组件**：如需要详情/编辑弹窗，拆到 `components/` 下。
5. **路由**：在 `router/modules/` 对应模块注册路由（含权限）。
6. **验证**：`pnpm dev` 启动，页面联调后端接口；`pnpm check` 通过类型检查。

## 12. 在线聊天模块交互约定

在线聊天基于 `WebSocket`（`/ws/chat`）+ 消息持久化（`chat_message` 表），核心文件：
`web/src/components/core/layouts/art-chat-window/index.vue`、`web/src/store/modules/chat.ts`、`web/src/utils/websocket.ts`、`web/src/api/chat.ts`。

### 12.1 在线用户列表展示

- 列表**只显示除登录用户本人之外的在线用户**（`refreshOnlineUsers` 与 WS `online` 消息均过滤 `userId === 当前用户`）。
- 每项显示：头像 + 昵称 + 岗位（`postName || deptName || userName`），点击头像即打开与该用户的私聊。
- **头像兜底**：用户未设置头像（`sys_user.avatar` 为空）时，统一显示内置默认头像 `@imgs/user/avatar.webp`（与顶部用户菜单一致，经 `avatarSrc(url) = url || defAva` 兜底，应用于在线列表/会话列表/聊天头部/消息气泡四处）；群聊会话无单人头像，显示群图标（`ri:team-line`）。用户后续上传头像后会自动显示其真实头像。
- 列表保持完整、不缩减：
  - 打开聊天时刷新一次（`refreshOnlineUsers`，走 HTTP `/chat/online` 兜底）；
  - 连接后每 **30s** 定时刷新（组件 `onlineRefreshTimer`）；
  - 收到他人私聊消息时，若发送者不在列表则自动补入。
- 右上角群图标按钮（`showOnlineUsers`）用于在「在线用户列表」与「会话列表」间切换；点击用户**不会**再自动切走在线列表。

### 12.2 给"我"的消息红色未读数

- Store 提供计算属性 `privateUnreadByUser: Record<userId, unreadCount>`：聚合各**私聊会话**的未读数。
- 在线用户列表每项右侧用**红色 `ElBadge`（`type="danger"`）** 显示该用户发给我的未读消息数。
- 点击该用户进入私聊即清零（`openPrivateChat` 置 `session.unreadCount = 0`）。
- 会话列表项同样显示未读 `ElBadge`（`type="primary"`）；会话未读也会计入顶部 `totalUnreadCount` 角标。

### 12.3 群聊（多人沟通）入口

- 左侧头部**「发起群聊」**按钮（`ri:group-add-line`）→ `ElMessageBox.prompt` 输入群聊名称。
- 确认后调用 `chatStore.openGroupChat(name)`：创建/打开群会话，并通过 WS `joinGroup` 加入。
- 群聊消息按 `groupName` 聚合，多人收发均进入同一会话（后端 `routeGroupMessage` 广播到群成员）。
- 打开群会话会经 `/chat/history?groupName=` 加载持久化群聊历史。

### 12.4 关闭逻辑

- **聊天窗口关闭**：左侧头部 X 与**右侧聊天区头部 X** 均调用 `closeChat()`，关闭整个抽屉（`isDrawerVisible = false`）。
- **单个会话关闭**：在「会话列表」每行尾部提供 ×（`closeSession(session.id)`），只移除该会话（群聊同时发送 WS `leaveGroup`），不关闭窗口。

> 说明：聊天头部右侧的 X 仅关闭**整个聊天窗口**；需要结束某个具体会话请使用会话列表行内的 ×。
